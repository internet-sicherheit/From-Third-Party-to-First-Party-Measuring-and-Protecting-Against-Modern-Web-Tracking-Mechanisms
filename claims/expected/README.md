# Frozen reference outputs

Each claim script regenerates one of these files and compares byte for byte.
A claim passes only on an exact match.

All four files were produced by the scripts in this repository, on the dataset
shipped with this artifact, and were checked against the authors' original
analysis outputs (see "Provenance" below).

| File | Produced by | Size |
|---|---|---|
| `rules_181.txt` | `06_RuleSet_Generation/RuleSet_Mining/rules_generator/create_rules.py` | 181 rules |
| `claim1_reference.csv` | `Code/Heuristik/cookie_heuristik_opti.py` | 12,979 rows |
| `cluster_reference_k8.txt` | `Code/Analysis/ecosystem/ecosystem_analysis_pipeline.py` | 24,914 clusters |
| `attribution_reference.csv` | `Code/Analysis/ecosystem/attribute_scripts.py` | 11,380 clusters |

## rules_181.txt

The 181 filter rules of paper Section 5.5. Generated from
`06_RuleSet_Generation/RuleSet_Mining/fpg_outputs_max_depth__161/itemsets_minsup_0.001.csv`
with `--min-lift 10 --max-params 3`.

Provenance: byte-identical to the rule set shipped with the paper,
`06_RuleSet_Generation/Rules_evaluation/rules_keys161_lookahead.txt`.

Note that `rules_keys161_lookahead_5.txt` in the same directory holds 209
rules; it corresponds to `--min-lift 5` and is *not* the published rule set.

## claim1_reference.csv

Output of the C3/C4 cookie heuristic over the first two shards of
`02_Data/potential_first_party_tracking_cookies/`.

Provenance: generated by the shipped code on the shipped shards, and verified
to be reproducible across repeated runs.

**This is a regression reference, not the paper's Section 4 result.** The
published numbers were computed over a different export
(`fp_cookies_holding_id_candidates_*.csv`, 8 shards) that is not part of this
artifact, and which survives here only as
`Code/Heuristik/cookies_holding_ids.csv` (281,815 rows, 31,850 with
`hold_id=True`). The heuristic groups cookie values per shard file, so its
output depends on how rows are distributed across shards; running it on the
shards shipped here disagrees with that frozen output on about 31% of the
overlapping cookies. See README, section "Scope of reproduction".

Please check [README](../../02_Data/README.md) for download extraction duo to the datasets.

## cluster_reference_k8.txt

SimHash clustering of `02_Data/ecosystem/simhashes_24112025.csv` (26,606
fingerprints) with f=64 and k=8, yielding 24,914 clusters (23,926 singletons,
988 with two or more members, largest 67).

Provenance: verified to contain exactly the same set of clusters as the
authors' original output `Code/Analysis/ecosystem/cluster_27112025_k8.txt`.
The two files differ only in ordering: cluster members come out of a Python
set, whose iteration order is not stable across interpreter runs, so the
pipeline now sorts members and clusters before writing. The clustering itself
is unchanged.

## attribution_reference.csv

Entity attribution of `cluster_script_url_etlds_fp_party.csv` (16,114 scripts
across 11,380 clusters) against the WhoTracksMe TrackerDB, giving per-cluster
organization shares. 1,038 of 16,114 scripts resolve to a known organization,
spanning 177 distinct organizations.

Provenance: verified cell for cell against the authors' original output
`Code/Analysis/ecosystem/fp_cluster_attribution_27112025.csv`; the two differ
only in row order, which the script now sorts for determinism.

Not to be confused with `result_fp_cluster_attribution_28112025.csv`, a
downstream single-label-per-cluster summary (`cluster,attribution`, 809 rows)
produced by a notebook, not by `attribute_scripts.py`.
